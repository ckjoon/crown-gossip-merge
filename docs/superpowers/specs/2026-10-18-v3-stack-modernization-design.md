# v3 스택 현대화 · 손맛 · 보상 연출 설계 (v3.0.0 → v3.1.0)

작성일: 2026-10-18 · 대상 버전: v3.0.0(기반·손맛·보상 연출 구조), v3.1.0(인테리어·캐릭터·아이템 아트)

## 목표

- 지금은 HTML과 전역 스크립트로 만든 "웹페이지 같은" 게임이다. 이를 **게임다운 손맛을 가진 웹 PWA**로 바꾼다.
- 핵심 경험은 **합성의 희열 → 확실한 인테리어 보상**이다. 보드에서의 손맛을 끌어올리고, 그 결과가 성의 방에서 눈에 띄는 변화로 돌아오게 한다.
- 구조를 바꾸되 v2.5.0의 게임 규칙과 밸런스는 그대로 유지한다. 기존 플레이어의 세이브는 그대로 이어지고, 쌓여 있던 문제 데이터는 한 번 정리한다.
- 나중에 서버 저장과 결제·광고를 붙일 수 있도록 재화와 세이브의 경계를 나눠 둔다.

## 확정된 결정

| 항목 | 결정 |
|---|---|
| 배포 형태 | 웹 PWA 유지 (Vercel). 앱스토어 포장 안 함 |
| 스택 | Vite + TypeScript + ES 모듈 |
| 합성 보드 | PixiJS v8 (WebGL) |
| HTML UI | Svelte 5 |
| 3D 성 | Three.js 유지 (TypeScript 모듈로 이전) |
| 애니메이션 | GSAP (npm 패키지) |
| 구조 | 계층 분리 + 도메인 이벤트 (섹션 1) |
| 릴리스 | v3.0.0 푸시·배포 확인 → v3.1.0 푸시·배포 확인, 두 단계 |

## 범위 밖

- 실제 결제와 광고 연동, 서버 저장. 경계(인터페이스)만 만든다.
- 게임 규칙과 밸런스 변경. 단, 섹션 2의 기존 세이브 정리는 포함한다.
- UI 전체를 게임 엔진 안으로 옮기는 C안. 이후 버전에서 검토한다.

## 1. 구조와 모듈

```
src/
  core/                 순수 TypeScript (DOM·Pixi·Svelte·Three 의존 없음)
    state.ts            GameState 타입과 초기 상태
    rules/              progression(v2.5 규칙 이전), chains·generators·customers·holidays·rooms 데이터
    actions/            spawn · move/merge · serveOrder · renovate · buy · holiday … 상태 변경 함수
    events.ts           도메인 이벤트 타입
    store.ts            상태 보관 + dispatch + 이벤트 발행 + 구독
  services/
    save/               SaveRepository 인터페이스 + IndexedDB/localStorage 구현 + 마이그레이션
    economy/            재화 지급·차감 창구 (지금은 로컬, 나중에 서버 API로 교체)
    audio/              효과음 엔진 이전 + 진동(navigator.vibrate)
  views/
    board/              PixiJS 보드(7×8 본게임, 5×5 이벤트 공용) + 손맛 연출
    fx/                 화면 전체 연출 오버레이 캔버스 (보드 ↔ HTML UI 사이 비행 연출)
    ui/                 Svelte 5 컴포넌트
    castle/             Three.js 성 (CastleView)
    reward/             보상 순간 연출 (복구·구역 완성·레벨업)
  main.ts               조립: store 생성 → 세이브 로드·마이그레이션 → 뷰 마운트
```

### 흐름

1. 사용자 입력 → `store.dispatch(action)`
2. core가 상태를 바꾸고, 도메인 이벤트를 발행한다.
3. Svelte UI는 **상태**를 구독해 다시 그린다.
4. Pixi 보드, fx, reward, castle은 **이벤트**를 받아 연출을 재생한다.
5. save 서비스가 변경을 모아 저장한다.

### 도메인 이벤트 (최소 목록)

`spawned`, `moved`, `merged`, `mergeRejected`, `crateOpened`, `orderServed`, `itemBought`, `currencyChanged`, `levelUp`, `spotRestored`, `zoneCompleted`, `zoneRevealed`, `holidayMissionCompleted`

각 이벤트는 연출에 필요한 정보(칸 번호, 체인, 레벨, 보상량 등)를 담는다.

### 원칙

- 규칙과 밸런스 수치는 `core/rules`에만 둔다.
- 연출은 상태를 바꾸지 않는다. 이벤트를 받아 재생만 한다.
- core는 시간·난수를 주입받는다(`now`, `rng`). 그래서 테스트에서 결과를 고정할 수 있다.

## 2. 데이터와 저장

### 상태 소유권

- 장소 복구 여부와 스타일은 v2에서 3D 엔진 내부 데이터(`ROOM_THEMES[*].spots[*].done`)에 있었다. v3에서는 이를 **`state.rooms: Record<spotId, { done: boolean; styleIdx: number }>`**로 옮긴다.
- 방·장소·대사 데이터는 `core/rules/rooms.ts`로 분리한다.
- 현재 보고 있는 구역은 `state.currentThemeKey`에 둔다.

### 세이브 호환

- 같은 저장소를 쓴다: IndexedDB `CrownGossipMergeDB` / store `player_progress` / key `main_save_v1`, localStorage 백업 `crown_gossip_save_backup_v1`. 둘 중 최신본을 읽는 규칙도 유지한다.
- 저장 레코드에 `schemaVersion`을 둔다. v2 세이브는 3이고, v3는 4로 저장한다.
- 불러오기는 **순수 함수 `restoreState(raw, now)`**로 처리한다. v2.5의 `mergeWithDefaultState`가 하던 처리를 모두 포함한다.
  - 필드 검증, 오프라인 번개 충전, 별 → 코인 환산, 조합 주문 재추첨, 없어진 체인 정리
- 마이그레이션은 `migrations: Array<(raw) => raw>` 단계로 순서대로 적용한다. v2 레코드의 `interiorRooms`는 `state.rooms`로 변환한다.
- 설정의 백업 코드 내보내기·가져오기는 v2 백업 코드도 받아들인다.

### 기존 플레이어 세이브 정리 (v2 → v3 마이그레이션에서 한 번만)

| 대상 | 정리 방법 | 이유 |
|---|---|---|
| 번개 100 초과 (v2.4 무료 충전으로 누적) | **100으로 맞추고**, 초과분 50개당 💎1을 보상(최대 💎30) | 번개 긴축을 되살리되 모은 걸 완전히 없애지는 않음 |
| 레거시 조합품(`combo`) 아이템 (보드·보관함) | 판매가만큼 🪙로 바꾸고 칸에서 제거 | 판매만 되는 죽은 칸 정리 |
| v2.4에서 이미 완성한 구역 | 구역당 💎50 소급 지급 | 구역 완성 보상 누락 보정 |
| 이벤트 무료 생성 횟수 12 초과 | 12로 맞춤 | 예전 규칙(+4/미션)으로 부풀어진 값 |
| 주문 객체의 `stars` 필드 | 제거 | 쓰지 않는 필드 |
| 순서가 뒤섞인 완료 장소 | **그대로 유지** | 진행 손실 없음. 다음 화는 기존 규칙대로 첫 미완료 장소 |

- 정리는 `schemaVersion < 4`인 세이브에만 한 번 적용된다. 결과는 `migrationReport`(바뀐 항목 목록)로 남긴다.
- 첫 실행 때 v3.0 패치노트 팝업 위에 **"세이브 정리 안내"**를 띄운다(예: "번개 1,000 → 100, 💎+18", "조합품 3개 → +105🪙", "구역 완성 소급 💎+50").
- 새 플레이어에게는 아무것도 적용하지 않는다.

### 저장 타이밍

- 상태 변경 후 **300ms 동안 모아 한 번 저장**한다.
- `visibilitychange`(hidden)와 `pagehide`에서 즉시 저장한다.
- 💎 지급, 장소 복구, 구역 완성처럼 중요한 변경은 즉시 저장한다.

### 재화 창구 (economy 서비스)

- 코인·보석·번개의 지급과 차감은 `economy.grant(currency, amount, reason)`와 `economy.spend(...)`만 거친다.
- 지금 구현은 로컬 상태를 바로 바꾼다. 나중에 결제를 붙일 때 이 창구만 서버 호출로 바꾼다. `reason`은 서버 검증과 로그에 쓰일 값이다.

## 3. Pixi 보드와 손맛 연출 (v3.0)

### 렌더링

- PixiJS v8 보드 컴포넌트 하나로 본게임 보드(7×8)와 명절 이벤트 보드(5×5)를 그린다.
- 아이템 그림은 v3.0에서 기존 SVG를 텍스처로 래스터화해 쓴다(체인×레벨별 캐시, 기기 픽셀 비율 반영). v3.1에서 텍스처만 새 아트로 바꾼다.
- 기존 보드 기능을 모두 Pixi로 구현한다: 봉인 상자, 거미줄, 주문 재료 ✔ 표시, 선택 칸, 이름표·레벨 표시, 생성기 ★ 표시.
- 캔버스 두 장:
  - **보드 캔버스:** 보드 영역만 담당하고 입력을 받는다.
  - **fx 오버레이 캔버스:** 화면 전체를 덮고 `pointer-events: none`이다. 보드와 HTML UI 사이를 오가는 비행 연출을 그린다.

### 손맛 연출

1. **드래그 & 스냅:**
   - 집으면 1.15배로 커지고 그림자가 생기며, 이동 방향으로 기운다.
   - 합칠 수 있는 칸은 숨 쉬듯 빛난다.
   - 놓으면 튕기며(back-out) 자리를 잡는다. 놓을 수 없으면 원래 칸으로 튕겨 돌아간다.
2. **합성 팝 & 파티클:**
   - 두 아이템이 목표 칸으로 빨려 들어가 찌그러졌다가 새 아이템이 튀어나온다.
   - 빛 링과 별가루가 퍼진다. 파티클 수는 레벨에 비례하고, Lv.5 이상이면 화면이 살짝 흔들린다.
3. **생성기 배출:**
   - 생성기가 출렁인다. 아이템은 포물선으로 빈칸까지 날아가 튀어 안착한다.
   - 배속 ×2·×4에서는 꼬리 빛과 색이 강해진다.
4. **주문 완료 비행:**
   - 재료가 보드에서 해당 손님 카드로 날아가 흡수된다.
   - 코인은 상단 🪙 표시로 날아가고, 재화 숫자가 통통 튀며 올라간다.

### 공통

- 진동: 합성 15ms, 고레벨 합성 30ms, 생성 10ms. 지원하는 기기에서만 동작한다.
- 효과음은 기존 신시사이저 효과음을 연출 타이밍에 맞춘다.
- 파티클은 객체 풀로 재사용한다.
- 시스템의 `prefers-reduced-motion` 또는 설정의 "연출 줄이기"가 켜지면 흔들림을 끄고, 파티클을 1/4로 줄이고, 비행 시간을 절반으로 줄인다.
- 목표 성능: Galaxy S25에서 60fps. 동시 연출이 몰려도 50fps 아래로 떨어지지 않는다.

## 4. UI, 성 화면, 보상 연출

### Svelte UI (v3.0)

- v2.5의 화면 구성과 배치(S25 세로 기준)를 유지한 채 컴포넌트로 옮긴다.
  - 상단 바, 주문 카드(💎 구매 줄 포함), 대화 바, 인스펙터, 하단 도구(성으로 가기·보관함·거미줄 해제·정렬·배속)
  - 모달: 도감, 보관함, 레벨, 설정, 패치노트, 💎 상점, 스토리 다시보기, 컷신, 명절 이벤트, 레벨업 배너, 세이브 정리 안내
- 모달과 배너에 Svelte 전환 애니메이션을 넣는다.
- 설정에 "연출 줄이기" 토글을 추가한다. 이 값은 저장한다.
- v2.5.0 리뷰에서 미뤄 둔 문제 6건을 함께 고친다.
  1. 레거시 조합품 ★ 표시: 레거시 아이템은 마이그레이션으로 정리되므로 표시 자체가 없어진다.
  2. 구역 완성 시 공개 대상: 다시 계산한 현재 구역이 방금 완성한 구역과 다를 때 그 구역을 공개한다.
  3. 구역 완성 연출 중 입력: 연출 동안 성 화면의 다른 입력을 막는다.
  4. 💎 부족 안내: 구매 버튼은 비활성처럼 보이되 눌리게 두고, 누르면 "💎 보석이 부족해요"를 띄운다.
  5. 주문 카드 탭마다 저장: 저장 묶음 처리로 해결한다.
  6. 보석 값 검증: 0 이상의 유한한 정수만 받는다(코인·번개도 같게).

### 성 화면 (v3.0)

- `interior3d.js`를 `views/castle/CastleView.ts`로 옮긴다. 렌더링은 `state.rooms`를 보고 한다.
- 복구 핀과 구역 입장 핀은 Svelte 오버레이로 만든다. 3D 좌표를 화면에 투영해 배치한다.
- 구역 순차 해금, 제N화 잠금, 💎 상점 등 v2.5의 규칙은 core 행동(`renovate`, `selectZone`)이 검사한다. 뷰는 결과만 보여 준다.

### 보상 연출 (v3.0, 기존 가구 모델 사용)

1. **복구 순간:**
   - 방이 어두워지고 해당 장소에 스포트라이트가 비친다.
   - 카메라가 다가가면 가구가 떨어지며 튀고(bounce) 반짝임이 퍼진다.
   - "제N화 복구 완료!" 리본과 보상 칩(경험치, 생성기 파츠)이 날아간다.
   - 캐릭터 반응 말풍선이 뜬 뒤 컷신이 이어진다.
2. **방이 살아나는 진행 표현:**
   - 복구한 장소 수(0~5)에 따라 방의 상태가 단계적으로 바뀐다.
   - 0개: 어둡고 차가운 조명, 먼지 파티클, 금 간 바닥 데칼
   - 5개: 따뜻하고 밝은 조명, 촛불과 빛가루 파티클, 장식 소품
   - 단계는 `core/rules/rooms.ts`의 `ambienceByProgress` 테이블로 정의한다.
3. **구역 완성:**
   - 기존 둘러보기에 "어두운 방(0단계) → 완성된 방(5단계)" 전환을 더한다.
   - 축하 파티클과 💎50이 상단 💎 표시로 날아가는 연출을 넣는다.
4. **캐릭터 시스템:**
   - `core/rules/characters.ts`에 캐릭터 목록을 둔다: id, 이름, 역할, 초상화 키, 이모지 대체값.
   - 컷신, 손님 카드, 반응 말풍선은 초상화를 보여 준다. 초상화가 없으면 이모지를 보여 준다.
   - 기존 대사의 `speaker`·`face` 문자열은 캐릭터 id로 정리한다.

## 5. 빌드·배포·PWA

- 의존성: vite, typescript, svelte(5), @sveltejs/vite-plugin-svelte, pixi.js(8), three, gsap, vite-plugin-pwa, vitest, @playwright/test, svelte-check. 구현 시점의 최신 안정 버전을 **정확한 버전으로 고정**한다.
- `package.json` 스크립트:
  - `dev`, `build`, `preview`
  - `test` (Vitest), `test:e2e` (Playwright), `check` (svelte-check + tsc)
- Vercel: Vite 프레임워크로 빌드하고 출력 디렉터리는 `dist`다. 기존 `vercel.json`의 보안 헤더와 `sw.js`·manifest 헤더 규칙을 유지한다.
- PWA:
  - vite-plugin-pwa(Workbox `generateSW`)로 빌드 결과물 전체를 미리 캐시한다.
  - 서비스 워커 파일 이름은 `/sw.js`, 스코프는 `/`로 유지한다. manifest의 `id: "/"`와 아이콘도 유지한다. 그래야 설치된 PWA가 새 서비스 워커로 자연스럽게 넘어간다.
  - 예전 캐시(`crown-gossip-pwa-v*`)는 새 서비스 워커의 activate 단계에서 지운다. IndexedDB와 localStorage는 건드리지 않는다.
  - 새 버전을 감지하면 화면을 새로고침한다. 단, 진행 중인 연출이나 모달이 없을 때만 한다.
- 정적 자산(아이콘, 나중의 아트)은 `public/`에 둔다.

## 7. v3.1 — 인테리어 · 캐릭터 · 아이템 아트

v3.0의 연출 구조(텍스처 교체 지점, 캐릭터 초상화 키, 방 분위기 단계, 가구 모델 교체 지점)에 아트를 채운다.
