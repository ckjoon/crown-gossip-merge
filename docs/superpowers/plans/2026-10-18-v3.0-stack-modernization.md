# v3.0 스택 현대화 · 손맛 · 보상 연출 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** v2.5.0 게임을 Vite + TypeScript + Svelte 5 + PixiJS v8 + Three.js 구조로 다시 짓는다. 규칙과 세이브는 그대로 잇고, 합성 보드의 손맛과 인테리어 보상 연출을 더한 v3.0.0을 만든다.

**Architecture:** `src/core`는 DOM이 없는 순수 TypeScript다. 상태, 규칙 데이터, 행동(action), 도메인 이벤트, store를 담는다. 행동은 상태 사본(draft)을 바꾸고 이벤트 목록을 돌려준다. store는 새 상태를 구독자(Svelte UI)에게 알리고, 이벤트를 연출 계층(Pixi 보드·fx·castle·reward)에 보낸다. `src/services`는 저장(IndexedDB/localStorage + v2 마이그레이션), 오디오, 진동을 맡는다.

**Tech Stack (정확한 버전 고정):** vite 8.3.4, typescript 6.0.3, svelte 5.57.2, @sveltejs/vite-plugin-svelte 7.3.1, pixi.js 8.22.0, three 0.186.1, @types/three 0.186.0, gsap 3.15.0, vite-plugin-pwa 2.0.0, workbox-precaching 7.4.1, workbox-core 7.4.1, vitest 5.0.5, fake-indexeddb 6.2.6, @playwright/test 1.64.1, svelte-check 4.7.7, @tsconfig/svelte 5.0.8, @types/node 24.x(최신 24 계열)

**Spec:** `docs/superpowers/specs/2026-10-18-v3-stack-modernization-design.md` (이 계획은 v3.0 범위. v3.1은 시안 확정 후 별도 계획)

## Global Constraints

- 모든 UI 문구, 주석, 커밋 메시지는 한국어로 쓴다. 커밋 형식은 `feat(v3.0): ...`, `refactor(v3.0): ...`, `test(v3.0): ...`이다. 커밋 메시지 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`를 붙인다.
- 작업 브랜치는 `feat/v3`이다. `main`은 v3.0 완성 전까지 건드리지 않는다.
- 게임 규칙과 수치는 v2.5.0과 같다. 원본은 `legacy/v2/`(Task 1에서 옮김)의 `game.js`, `progression.js`, `db.js`, `interior3d.js`, `sprites.js`다. 바뀌는 것은 스펙 섹션 2의 세이브 정리, 섹션 4의 미뤄 둔 문제 6건 수정, 그리고 새 연출뿐이다.
- `src/core`는 `window`, `document`, `pixi.js`, `svelte`, `three`, `gsap`를 import하지 않는다. 시간·난수·uid는 `Ctx`로 주입받는다.
- 저장 키는 바꾸지 않는다: IndexedDB `CrownGossipMergeDB` v2 / store `player_progress` / key `main_save_v1`, localStorage `crown_gossip_save_backup_v1`. 새 레코드는 `schemaVersion: 4`로 저장한다.
- 세이브 정리 수치: 번개 100 초과분은 100으로 맞추고 초과 50개당 💎1(최대 💎30), 레거시 combo 아이템은 판매가만큼 🪙로 바꾸고 제거, v2에서 이미 완성된 구역마다 💎50, 이벤트 freeSpawns는 최대 12, 주문의 `stars` 필드 제거. `schemaVersion < 4`에서만 한 번 적용한다.
- 저장: 변경 후 300ms 묶음 저장, `visibilitychange`(hidden)·`pagehide`에서 즉시 저장, 💎 지급·장소 복구·구역 완성은 즉시 저장.
- 서비스 워커 파일은 `/sw.js`(스코프 `/`), manifest `id: "/"`와 아이콘은 그대로 둔다. 예전 `crown-gossip-pwa-v*` 캐시는 지우고 IndexedDB·localStorage는 건드리지 않는다.
- 진동: 합성 15ms, Lv.5 이상 합성 30ms, 생성 10ms. 연출 줄이기: 흔들림 끔, 파티클 1/4, 비행 시간 1/2.
- 목표 화면: Galaxy S25 세로(412×915). 가로 스크롤이 없어야 한다.
- 레이지 로딩(dynamic import)을 쓰지 않는다. 배포가 바뀌면 예전 청크가 404가 되기 때문이다.

## Review Focus

1. **실제 v2 세이브 이어받기:** 번개 1,000, combo 아이템, 별, 순서가 뒤섞인 완료 장소, 완성된 구역이 있는 세이브도 오류 없이 열려야 한다. 정리는 한 번만 일어나고, 정리 안내가 정확한 숫자로 떠야 한다. Task 6 테스트와 Task 13 E2E에서 다룬다.
2. **보드 입력 경계:** 드래그 도중 화면 전환이나 모달 열기, 멀티터치, 같은 칸에 놓기, 봉인 상자로 드래그, 빠른 연속 탭. 상태가 깨지거나 아이템이 사라지면 안 된다. Task 8에서 다룬다.
3. **연출 중 상태 변경:** 합성 연출이 끝나기 전에 다음 행동이 들어와도 보드 표시가 실제 상태와 어긋나지 않아야 한다. 뷰는 항상 store 상태로 다시 맞춘다. Task 9에서 다룬다.
4. **PWA 업데이트:** v2.5 서비스 워커가 설치된 기기에서 v3로 넘어갈 때 흰 화면이나 예전 청크 404가 없어야 하고, 세이브는 유지돼야 한다. Task 13에서 다룬다.
5. **저장 타이밍:** 장소 복구 직후나 💎 구매 직후 앱을 닫아도 그 결과가 남아야 한다. Task 6과 Task 13에서 다룬다.
