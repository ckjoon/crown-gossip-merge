# v3.4 레고식 방 + 성 평면도 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 구역 방이 입구 홀에서 시작해 장소를 복구할 때마다 방 조각이 레고처럼 붙어 넓어지고, 성 전체지도는 4개 구역 날개가 이어진 평면도로 보이게 한다.

**Architecture:**
- **`views/castle/modules.ts`** (순수 계산, three 없음, 단위 테스트):
  - 구역별 조각 배치표 `ZONE_MODULES`
  - 상태 `moduleStates`
  - 벽·문 계산 `moduleEdges`
  - 장소 위치 `spotAnchor`
  - 카메라 범위 `zoneBounds`/`fitZoom`
- **`roomBuilder.ts`:** 위 계산을 three 메시로 그린다.
- **`floorplan.ts`:** 전체지도를 그린다.
- **CastleView:** 고정 10×10 방 대신 이것들을 쓰고, 복구 연출에 "조각 짓기"를 넣는다.

**Tech Stack:** Three.js r186, gsap, Vitest(node 환경), Playwright.

**Spec:** `docs/superpowers/specs/2026-10-20-v3.4-modular-rooms-characters-design.md` (0단계 + 1부)

## Global Constraints
- 세이브 형식·core 규칙 변경 없음. 모양은 `rooms[spotId].done`에서 계산.
- 한국어 UI·주석·커밋, 커밋 `feat(v3.4.0): ...`.
- 구역 화면 그리기 호출 ≤ 400, 삼각형 ≤ 200k (데스크톱 headless 측정).
- 412×915 세로 화면 기준.
- 복구 연출 중 입력 잠금·그림자 갱신·모델 교체 보류 규칙 유지.

## Rulings (계획 단계)
- **0단계 방 조각 에셋 → 절차적 툰 블록으로 확정** (명세의 대체안).
  - 이유: 레고 블록 느낌에 맞고, 내려받을 파일이 없으며(오프라인·첫 로딩 0), 대체 경로를 두 벌 만들 필요가 없음.
  - 틀렸을 때 비용: 벽 디테일이 KayKit보다 단순함. 캐릭터 에셋 확인은 v3.5 계획에서.
- **조각 크기 1칸 = 5단위.** 장소 가구 배치표 좌표는 ±1.8 안이라 그대로 들어간다.
- **분위기 소품(`ZONE_PROPS`)의 좌표 의미 변경.** step k 소품은 조각 k(그 단계에서 지어진 조각) 기준 지역 좌표가 된다. 벽걸이 소품은 바닥 소품으로 바꾼다(그 조각 벽이 열려 있을 수 있음).
- **decor.ts의 벽 장식 대체.** 고정 10×10 벽에 붙던 장식은 조각의 바깥 벽마다 붙는 구역별 장식(발광 재질, `setDecorGlow` 유지)으로 바뀐다.

## Review Focus
- 기존 세이브의 구역(예: 3곳 복구)을 열면 연출 없이 홀 + 조각 3개 + 폐허 1개 + 청사진 1개가 바로 보임 → Task 4 단위 테스트 `moduleStates`와 E2E.
- 구역 완성(5곳) 후에는 폐허가 없고, 카메라가 전체를 잡고 끌기로 끝까지 볼 수 있음 → Task 1 `zoneBounds`/`panClamp` 테스트.
- 복구 연출 도중 지도로 전환·다른 구역으로 이동해도 조각이 엉뚱한 구역에 지어지지 않음 → Task 4에서 `playRestore`가 `this.mode/zone`을 확인.
- 창문형 장소(벽에 붙는 가구)는 항상 막힌 바깥 벽 앞에 걸림 → Task 1 테스트 "창문 장소 조각의 -z 쪽에 다른 조각 없음".
- 잠긴 구역은 지도에서 청사진 + 자물쇠로만 보이고 탭해도 들어가지지 않음 → Task 5 테스트 + 기존 core 잠금 규칙.
