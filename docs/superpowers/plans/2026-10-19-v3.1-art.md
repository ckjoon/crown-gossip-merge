# v3.1 인테리어 · 캐릭터 · 아이템 아트 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** v3.0 기반 위에 "코지 판타지 툰" 아트를 입힌다. 툰 셰이딩·외곽선 인테리어와 장소별 고유 가구 20종, 치비 초상화(표정 4종)와 방 안 캐릭터, 스티커 스타일 아이템을 넣는다.

**Architecture:** 아트는 모두 views 계층에서 코드로 생성한다. core 변경은 캐릭터 `portraitKey`와 표정 선택 규칙(순수 함수)뿐이다. 텍스처 키, 장소 id, 캐릭터 id는 v3.0과 같게 유지해 연결 지점을 바꾸지 않는다.

**Tech Stack:** v3.0과 동일(Three.js r186 MeshToonMaterial, SVG 생성, PixiJS 텍스처 캐시)

**Spec:** `docs/superpowers/specs/2026-10-19-v3.1-art-design.md`

## Global Constraints

- 브랜치는 `feat/v3.1`(v3.0 병합 후 `main`에서 분기)이다. 커밋 형식은 `feat(v3.1): ...`이고, 한국어 주석과 문구를 쓴다.
- 외부 이미지·모델 파일은 쓰지 않는다. 그림은 모두 코드(SVG·Three 프리미티브)로 만든다.
- 규칙과 밸런스는 바꾸지 않는다. 기존 단위 테스트 94개와 E2E 3개가 계속 통과해야 한다.
- 성능: 성 화면에서 외곽선·툰 재질 추가 후에도 데스크톱 헤드리스 기준 FPS를 기록하고, 크게 떨어지면 외곽선을 가구에만 적용한다.

## Review Focus

1. 툰 재질 변환 후 금속·발광 재질(창문 빛, 촛불, 보석)이 어둡게 죽지 않는지 확인한다.
2. 외곽선 메쉬가 그림자·레이캐스트·가구 교체(renderSpot) 때 누수되지 않는지 확인한다(dispose).
3. 초상화 SVG가 data URL 길이 제한이나 특수문자 인코딩 때문에 깨지지 않는지 확인한다.
4. 아이템 장식 레이어가 Lv.1~8 구분을 해치지 않는지(기존 "모두 다름" 테스트), 작은 칸(약 50px)에서 뭉개지지 않는지 확인한다.
5. 방 안 캐릭터 빌보드가 핀·스타일 선택 바를 가리거나 클릭을 막지 않는지 확인한다.

### Task 1: 초상화 생성기 + 표정 규칙 + 캐릭터 연결

**Files:** Create `src/views/art/portraits.ts`, `src/core/rules/expressions.ts`; Modify `src/core/rules/characters.ts`(portraitKey = id), `src/views/ui/components/Portrait.svelte`, `src/views/ui/modals/Cutscene.svelte`; Test `tests/unit/portraits.test.ts`, `tests/unit/expressions.test.ts`

- `expressionFor(line: string): "neutral" | "happy" | "surprised" | "worried"`의 우선순위는 다음과 같다.
  1. "걱정", "하지만", "…", "큰일"이 있으면 worried
  2. "?"가 있으면 surprised
  3. "!"가 있으면 happy
  4. 그 밖은 neutral
- `getPortraitSVG(id, expr)`: viewBox 0 0 100 100 치비 얼굴. 구성은 다음과 같다.
  - 배경 원(캐릭터 색)
  - 머리 뒤쪽
  - 얼굴(피부)
  - 눈: 표정별로 neutral 원, happy ^^ 곡선, surprised 큰 원, worried 처진 눈썹
  - 입: neutral 작은 선, happy 열린 웃음, surprised o, worried 물결
  - 볼터치
  - 앞머리
  - 소품
- 캐릭터 정의 표: 17명(selene, quinn, nero, quinn_nero, lucian, olivia, harrison, carmen, marco, ella, pip, rowan, lily, verna, arthur, margaret, oberon). 각자 피부·머리 모양(long|short|bob|spiky|none)·머리 색·눈 색·소품 목록을 둔다. nero는 고양이 얼굴, pip는 갈매기 얼굴(별도 그리기), quinn_nero는 퀸 얼굴 + 고양이 귀 배지다.
- 테스트:
  - 17명 × 4표정이 모두 `<svg`로 시작한다.
  - 같은 캐릭터의 표정 4개가 서로 다르다.
  - 캐릭터끼리 neutral이 서로 다르다.
  - 표정 규칙 5개 케이스가 맞다.
- `Portrait.svelte`는 `portraitKey`가 있으면 `data:image/svg+xml;utf8,` + encodeURIComponent(SVG)를 img로 그린다. `expression` prop을 받는다.
- 컷신: 현재 대사에 `expressionFor(line)`을 적용해 초상화 표정을 바꾸고, 바뀔 때 살짝 튀는 애니메이션을 준다.
- 커밋: `feat(v3.1): 치비 초상화 생성기와 대사 표정`

### Task 2: 아이템 스티커 스타일 통일 레이어

**Files:** Modify `src/views/art/sprites.ts`(`svgWrap` + 레벨 장식); Test: 기존 `tests/unit/sprites.test.ts` 유지 + 레벨 장식 테스트 추가

- `svgWrap(inner, id, c1, c2, opts?: { level?: number; isGenerator?: boolean })`
  - `<defs>`에 외곽선 필터를 추가한다(feMorphology dilate 1.6 → feFlood 0x2a1240 → feComposite → feMerge 원본 위).
  - 바닥 그림자 타원, 광택 하이라이트, Lv.5 이상 오라 원(점선, 연한 금색), Lv.7 이상 반짝이 별 2~3개, 생성기는 금색 테두리 링을 넣는다.
- 각 체인 SVG 함수가 `svgWrap`을 부를 때 level을 넘기도록 수정한다(호출부 전체).
- 테스트:
  - Lv.5 그림에는 오라 마크가 있고 Lv.4에는 없다.
  - Lv.7에는 반짝이가 있다.
  - 기존 "모두 다름" 테스트가 통과한다.
- 브라우저: 도감과 보드 스크린샷으로 작은 칸에서도 또렷한지 확인한다.
- 커밋: `feat(v3.1): 아이템 스티커 스타일(외곽선·광택·레벨 오라)`

### Task 3: 툰 셰이딩 · 외곽선 · 반구광 · 구역 고정 장식

**Files:** Create `src/views/castle/toon.ts`, `src/views/castle/decor.ts`; Modify `CastleView.ts`, `scenes.ts`

- `toon.ts`:
  - `toonify(root)`: MeshStandardMaterial을 MeshToonMaterial로 바꾼다. 색·emissive·emissiveIntensity·transparent·opacity는 유지하고, 3단 gradientMap(DataTexture, NearestFilter)을 공유한다.
  - `addOutline(group, thickness)`: 메쉬마다 BackSide 검은 재질을 쓴 확대 복제를 자식으로 붙인다. 기하는 공유하고, 외곽선 메쉬에는 `userData.outline` 표시를 한다.
  - `disposeGroup(group)`
- `decor.ts`: `buildZoneDecor(zone, group)`는 구역별 고정 장식 3~5개를 만들고, `setDecorGlow(level)`를 제공한다.
- `CastleView`:
  - `showZone`에서 방 껍데기와 장식에 `toonify`를 적용하고, 가구 `renderSpot`에는 `toonify`와 `addOutline`을 적용한다.
  - 반구광을 추가한다(하늘 0xd8c8ff, 땅 0x2b1640, 0.6π).
  - 지도에도 `toonify`를 적용한다.
- 성능: 성 화면 FPS를 측정해 기록한다.
- 커밋: `feat(v3.1): 툰 셰이딩·외곽선 인테리어와 구역 장식`

### Task 4: 장소별 고유 가구 20종

**Files:** Modify `src/views/castle/furniture.ts`(장소 빌더 맵), `layout.ts`(필요 시 크기·위치), `CastleView.renderSpot`; Test `tests/unit/furniture.test.ts`(node에서 three를 import해 그룹 생성만 검증)

- `SPOT_BUILDERS: Record<spotId, (group, pal) => void>`에 20개 장소를 모두 등록한다.
  - 각 빌더는 장소 이름에 맞는 형태를 만든다(예: 스테인드글라스 창문, 분수대, 파라솔 브런치석, 천체 관측기, 연회 테이블, 차원 포털).
  - 팔레트 primary/secondary/accent/wood를 쓴다.
  - 기존 8종 타입 빌더는 해당 장소에 맞게 손본다.
- `renderSpot`은 `SPOT_BUILDERS[spotId] ?? 타입 빌더` 순서로 고른다.
- 테스트:
  - 20개 장소 모두 빌더가 있고, 스타일 3종 각각 메쉬가 1개 이상이다.
  - 같은 장소의 스타일 3종은 재질 색이 서로 다르다.
- 브라우저: 4개 구역 완성 상태의 스크린샷.
- 커밋: `feat(v3.1): 장소별 고유 3D 가구 20종`

### Task 5: 방 안 캐릭터 빌보드

**Files:** Create `src/views/castle/resident.ts`; Modify `CastleView.ts`, `RewardDirector.ts`

- `Resident`:
  - 초상화 SVG(neutral·happy)를 CanvasTexture로 만들고, `THREE.Sprite`(크기 1.6)로 방 한쪽(구역별 위치)에 둔다.

- 지도 모드에서는 숨긴다. 핀 오버레이보다 아래에 그려지므로 클릭을 막지 않는다(3D 캔버스 안).
- `RewardDirector`: 복구 순간 가구가 떨어진 뒤 `resident.cheer()`를 호출한다.
