# v3.6 3D 캐릭터 + 초상화 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 방 안의 동그란 빌보드 캐릭터를 애니메이션 3D 캐릭터로 바꾸고, 주문 카드와 대사창 초상화도 같은 3D 모델에서 구운 그림으로 바꾼다.

**Architecture:**
- **에셋:** KayKit Adventurers 1.0(CC0) 체형 5종을 `tools/prepare-characters.mjs`(@gltf-transform)로 가볍게 만든다. 체형은 애니메이션·무기를 뺀 메시+뼈대로 남기고, 공용 애니메이션은 `anims.glb` 하나로 모은다.
- **캐릭터 데이터:** `views/castle/characters3d.ts`의 `CHARACTER_LOOKS`가 17명을 정의한다. 체형, 텍스처 색 변환, 보일 부속, 절차적 소품(모자·왕관·안경 등)을 담는다. 고양이 네로와 갈매기 핍은 절차적 툰 동물이다.
- **방 안 동작:** `CharacterActor`(`AnimationMixer`)가 대기, 지어진 조각 사이 걷기, 탭하면 손 흔들기·대사, 복구 때 환호를 맡는다. 한 구역에 최대 3명이다.
- **초상화:** `tools/bake-portraits.mjs`가 개발 서버에서 같은 코드로 17명 × 표정 4종을 192px JPEG로 굽는다(`public/portraits`). `Portrait.svelte`는 구운 그림을 먼저 쓰고, 없으면 벡터 초상화를 쓴다.

**Spec:** `docs/superpowers/specs/2026-10-20-v3.4-modular-rooms-characters-design.md` 2부

## Global Constraints
- 에셋은 CC0만 쓴다. 출처는 `public/models/CREDITS.md`에 추가한다.
- 캐릭터 모델은 구역을 볼 때 받는다(런타임 캐시, `MODEL_CACHE` 경로 `/models/`). 첫 설치 용량은 늘리지 않는다.
- 초상화는 프리캐시한다. 합계 1MB 이하로 한다.
- 세이브와 core 규칙은 바꾸지 않는다. 한국어 UI·주석·커밋, `feat(v3.6.0): ...`.
- 휴대폰 성능: 그리기 호출 증가는 캐릭터당 20 이하, 화면에 최대 3명.

## Rulings (계획 단계)
- **0단계 결과:** KayKit Adventurers 1.0을 쓴다. CC0이고 glTF이며 체형 5종이 같은 뼈대를 쓰고, 애니메이션 76종이 들어 있다. 미리보기 렌더 품질도 확인했다.
  - Quaternius 세트는 직접 받을 수 있는 경로가 없어서 보류한다.
  - 틀렸을 때 비용: 체형이 5종뿐이라 색과 소품으로 구분해야 한다.
- **동물(네로·핍):** CC0 애니메이션 동물을 찾지 못했다. 절차적 툰 모델 + 코드 애니메이션(숨쉬기·꼬리·날개)으로 만든다.
- **표정:** KayKit 얼굴은 텍스처라 표정이 바뀌지 않는다. 포즈(대기·환호·놀람·고민)와 이모트(✨ ❗ 💦)로 표정을 대신한다.
- **무기:** 무기·방패 노드는 숨긴다(아늑한 마녀의 성 분위기).

## Review Focus
- 모델 로딩 전·실패 시 캐릭터가 없거나, 예전 빌보드 대체가 깨지지 않는다(빈 공간이나 흰 사각형 없음).
- 구역 전환 중이나 복구 연출 중 걷기 트윈과 애니메이션이 정리된다(메모리·트윈 누수 없음).
- 걷기 목표는 지어진 조각 안에서만 고른다. 가구 위로 걷지 않는다.
- 초상화 파일이 없는 캐릭터는 벡터 초상화로 대체된다. 오프라인에서도 초상화가 보인다.
- 탭으로 캐릭터를 고를 때, 방 끌기와 핀 탭이 그대로 동작한다.

### Task 1: 캐릭터 에셋 준비
- `@gltf-transform/core` + `functions`를 dev 의존성으로 추가한다.
- `tools/prepare-characters.mjs <kaykit gltf 폴더>`:
  - 체형 5개: 애니메이션, 무기·방패·화살·석궁 노드를 제거하고 `prune` → `public/models/characters/<Body>.glb`
  - Mage.glb에서 애니메이션 클립만 남긴 `anims.glb`: Idle, Walking_A, Cheer, Interact, Hit_A, Spellcasting, Sit_Chair_Idle, Use_Item
- **테스트:** `characters.test.ts`
  - 파일이 있고 크기가 체형당 < 600KB, anims < 1.5MB.
  - anims.glb의 클립 이름에 필요한 8개가 모두 있다.
  - 체형 glb에 애니메이션이 없고 무기 노드가 없다(glb JSON 파싱).

### Task 2: 캐릭터 외형 데이터 + 생성기
- `src/views/castle/characters3d.ts`:
  - `CHARACTER_LOOKS: Record<characterId, Look3D>`
    - `kind: "human"`: body, hue(도), sat, show(부속 노드 이름), acc(절차적 소품 목록), scale
    - `kind: "cat" | "bird"`
  - `CharacterLibrary.preload(ids)`, `buildCharacter(id): THREE.Group | null`(동기), 절차적 소품·동물 빌더
  - 텍스처 색 변환은 캔버스 `filter: hue-rotate() saturate()`이고, (body, hue, sat)별로 캐시한다.
- **테스트:** 17명 모두 외형이 있다. (body, hue, acc) 조합이 서로 다르다. 소품 이름은 모두 빌더가 있다. 동물 빌더는 노드에서 메시를 만든다.

### Task 3: 방 안 3D 캐릭터
- `src/views/castle/actor.ts`: `CharacterActor`
  - 상태: idle / walk / cheer / wave
  - 걷기 목표는 지어진 조각 가운데 + 오프셋 `(1.3, 1.3)`
  - 6~11초마다 걷기 시작, 속도 1.4/s, 진행 방향을 바라본다.
  - `cheer()`, `wave()`, `tick(dt)`, `dispose()`
- **CastleView:**
  - `Resident` 빌보드를 `CharacterActor`로 바꾼다. 구역 주민 + 그 구역에서 이미 복구한 장소 대사에 나온 손님 최대 2명.
  - 모델이 준비되면 등장한다.
  - `pickActor(clientX, clientY)` 레이캐스트
- **CastleScreen:** 끌지 않은 탭이면 `pickActor` → wave + 말풍선(캐릭터 이름, 짧은 대사).
- **테스트:**
  - 걷기 목표 함수 `walkTargets(zone, states)`가 built 조각 안의 점만 준다.
  - 손님 고르기 `zoneGuests(zone, rooms)`가 중복 없고 최대 2명이다.
  - E2E: 성 화면에 SkinnedMesh 또는 동물 그룹이 있고, 에러가 없다.

### Task 4: 초상화 굽기
- `tools/bake-portraits.mjs`(Playwright + 개발 서버):
  - `characters3d.ts`로 각 캐릭터 상반신을 렌더한다.
  - 포즈: neutral = Idle, happy = Cheer, surprised = Hit_A, worried = Interact
  - 표정 이모트를 겹치고, 캐릭터 색 원형 배경을 깐다. 192px JPEG.
  - 저장: `public/portraits/<id>_<expr>.jpg` + `src/views/art/portraitManifest.ts`(구운 id 목록)
- **PWA:** `globPatterns`에 `portraits/*.jpg`를 추가한다.
- **Portrait.svelte:** 매니페스트에 있으면 jpg, 없으면 벡터.
- **테스트:** 매니페스트의 모든 id × 4표정 파일이 있고, 합계 < 1MB이고, `CHARACTERS` 17명이 모두 매니페스트에 있다.
