# v3.4–v3.5 레고식 방 + 3D 캐릭터 설계

**날짜:** 2026-10-20
**요청:** 2026-10-20 대화.
- 사용자 원문: "Characters and their portrait needs upgrade. Each room cant just be squares it should be expanding and connecting like Lego blocks of interior design as the characters progress"
- 선택 1: 방 확장 범위는 "구역 안 + 성 전체 연결".
- 선택 2: 캐릭터는 "3D 애니메이션 캐릭터".
- 설계안 승인: "ㅇㅋ".

## 목표
- 복구가 "공간이 넓어지는 보상"으로 느껴지게 해요.
  - 구역은 작은 홀 하나에서 시작해요.
  - 장소를 복구할 때마다 방 조각이 하나씩 붙어 넓어져요.
  - 성 전체지도에서는 4개 구역이 복도로 이어진 하나의 성으로 보여요.
- 캐릭터를 3D 애니메이션 모델로 바꿔요.
  - 방 안에서 움직이며 반응해요.
  - 주문 카드와 대사창 초상화는 같은 모델을 찍은 이미지로 맞춰요.

## 범위 밖
- 세이브 형식과 core 규칙은 바꾸지 않아요. 모양은 이미 저장된 "구역별 복구 수"에서 계산해요.
- 방 조각을 플레이어가 직접 배치하는 편집 모드는 넣지 않아요.
- 유료 에셋과 2D 일러스트는 쓰지 않아요.

## 0단계 · 에셋 확인 (spike)
아래 팩을 받아서 다음을 확인해요: 라이선스 CC0, glTF 제공 여부(없으면 Blender 변환 가능 여부), 텍스처와 삼각형 수, 함께 쓸 때 스타일이 어울리는지.

| 용도 | 1순위 | 대체 |
|---|---|---|
| 방 조각 (바닥·벽·아치·기둥·계단) | KayKit Dungeon Remastered (CC0) | 직접 만든 툰 블록 (지금 방 껍데기 방식) |
| 사람 캐릭터 15명 | Quaternius Universal Base Characters + Modular Outfits Fantasy + Universal Animation Library (CC0, 뼈대 공유) | KayKit Adventurers + Character Animations (CC0) |
| 고양이 네로 · 갈매기 핍 | Quaternius 동물 팩 (CC0) | 직접 만든 툰 동물 + 코드 애니메이션 |
| 표정 | 모델의 눈·입 텍스처나 모프 | 포즈 + 머리 위 이모트(💦 ❗ ♥ …) |

**결과 기록:**
- 확인 결과와 고른 대체안은 계획 문서의 Ruling으로 남겨요.
- 1순위가 안 맞으면 대체안으로 가요. 사용자에게 다시 묻지 않아요.

## 1부 · 레고식 방 (v3.4)

### 데이터 (views/castle/modules.ts)
- **구역 구성:** 구역마다 방 조각 6개가 있어요. 0번은 항상 지어져 있는 **입구 홀**이고, 1~5번은 장소 1~5(rooms.ts 순서)에 하나씩 대응해요.
- **조각 정의:** `ModuleDef { id, spotId | null, gx, gz, w, d, kind, parent }`
  - 칸 단위 격자 좌표를 써요. 1칸은 월드 6단위예요.
  - `parent`는 이 조각이 붙는 이웃 조각이에요. 이웃과 맞닿은 변에 아치 문이 나요.
  - 조각들은 트리로 연결되고, 서로 겹치지 않아요.
- **kind:** `hall | alcove | tower | corridor | terrace`. 크기와 장식 차이만 있어요.
  - tower: 원형 기둥 + 높은 벽.
  - terrace: 낮은 난간.
  - corridor: 1×2 칸.
- **구역별 벽 스타일:**
  - 공방·연회장: 돌벽 + 아치.
  - 하버: 낮은 난간 + 차양.
  - 정원: 생울타리 + 덩굴 아치.
- **조각 상태:** `moduleState(def, restoredCount, nextSpotIdx)` → `"built" | "ruin" | "ghost"`.
  - 입구 홀과 복구된 장소: built.
  - 다음에 복구할 장소: ruin.
  - 나머지: ghost.
  - 잠긴 구역은 모두 ghost예요.
- **장소 위치:**
  - 장소 위치 = 조각 중심 + 장소별 오프셋이에요. `SPOT_LAYOUT.pos`는 이 계산값으로 바뀌어요.
  - 가구 배치표(`SPOT_RECIPES`)는 장소 기준 상대 좌표라 그대로 써요.
- **분위기 소품(`ZONE_PROPS`):** 입구 홀과 각 조각에 나눠 둬요. built 조각에만 나타나요.

### 그리기 (views/castle/roomBuilder.ts)
- **`buildModules(group, zone, restoredCount)`**
  - built: 바닥 타일 + 바깥쪽 벽(카메라 반대쪽 두 변만) + 맞닿은 변의 아치 문 + 장식.
  - ruin: 깨진 바닥 + 낮게 무너진 벽 + 잔해. 지금의 `CLUTTER`가 여기로 옮겨가요.
  - ghost: 반투명 청사진 바닥 + 점선 테두리만. 그림자와 충돌이 없어요.
- **벽 높이:** 카메라 쪽 벽은 그리지 않아요(디오라마 컷어웨이). 이웃과 맞닿은 벽은 높이를 낮춰 안쪽이 가려지지 않게 해요.
- **에셋:** 0단계 결과에 따라 KayKit 조각이나 절차적 툰 블록을 써요. 둘 다 같은 `buildModules` 인터페이스 뒤에 둬요.
- **모델 로딩:** 기존 `ModelLibrary`로 구역별로 불러와요. 로딩 전에는 절차적 블록을 써요(지금 가구와 같은 원칙).

### 복구 연출 (playRestore 확장)
1. 카메라가 ruin 조각으로 가요.
2. 잔해가 가라앉아요.
3. 바닥 타일이 순서대로 떨어지며 깔려요.
4. 벽이 아래에서 솟아요.
5. 부모 조각과 맞닿은 벽이 아치 문으로 바뀌어요(벽 조각이 내려가고 아치가 올라와요).
6. 가구가 떨어져요(기존).
7. 다음 장소 조각이 ghost에서 ruin으로 바뀌어요(점선이 무너진 벽으로 차오름).
8. 카메라가 넓어진 전체를 다시 잡아요.

- 연출 중 입력 잠금과 그림자 갱신은 기존 규칙을 따라요.
- 복구 중 모델이 도착해도 연출이 끝난 뒤에 교체해요.

### 카메라
- **줌:** `fitBounds(built ∪ ruin)`로 기본 줌을 계산해요. 조각이 늘어날수록 멀어지고, 412×915 세로 화면에서 지어진 범위가 꽉 차요.
- **둘러보기:** 끌기 범위(`panBy` 제한)를 지금의 고정 ±3.2 대신 범위 상자에서 계산해요.
- **장소 포커스:** `focusSpot`은 장소 위치를 바꾼 뒤에도 그대로 동작해요.

### 성 전체지도
- **평면도:** 지금의 탑 모양 성 대신, 가운데 안뜰 하나와 4개 구역 날개가 복도로 이어진 평면도 디오라마를 보여요.
- **구역 날개:** 같은 `ZoneModules` 데이터를 작게 줄여 그려요.
  - built: 구역 색 블록.
  - ruin: 회색 블록.
  - ghost: 점선.
  - 잠긴 구역: 안개 처리 + 자물쇠.
- **조작:** 날개를 탭하면 그 구역으로 들어가요(지금 핀 동작 유지). `castlePinPos`는 날개 중심에서 계산해요.

### 테스트
- **단위 (`modules.test.ts`):**
  - 구역마다 조각 6개, 장소마다 정확히 하나의 조각.
  - 트리로 연결되고, 칸이 겹치지 않음.
  - 문은 부모와 맞닿은 변에 있음.
  - `moduleState`가 복구 수 0~5와 잠긴 구역에서 올바름.
  - 장소 위치가 자기 조각 안에 있음.
- **단위:** `fitBounds`와 끌기 제한 계산.
- **E2E:** 제1화 복구 전후로 `__castle()`의 built 조각 수가 1 → 2로 늘어남.

## 2부 · 3D 캐릭터 (v3.5)

### 캐릭터 정의 (views/castle/characters3d.ts)
- **`CHARACTER_LOOKS: Record<characterId, Look3D>`**
  - 체형 / 의상 부위 / 머리 / 색 / 모자·소품(가구 팩 소품 재사용 가능).
  - 동물: `kind: "cat" | "bird"`.
- **구분:** 17명이 실루엣과 색으로 서로 구분되게 해요. 테스트로 조합 중복이 없는지 확인해요.

### 방 안 동작 (resident.ts 대체)
- **동작:** 대기(idle) → 가끔 지어진 조각의 빈 바닥 지점으로 걷기 → 도착하면 대기.
  - 탭하면 손 흔들기 + 대사 말풍선.
  - 복구 때 환호(cheer).
  - 걷기 경로는 지어진 조각과 문 사이만 지나요.
- **등장 인원:** 한 구역에 최대 3명(구역 주인 + 이야기 진행에 맞춘 손님 2명). 3명 넘게 보이지 않아요.
- **애니메이션:** `AnimationMixer`를 캐릭터마다 하나 써요. 클립은 구역 간에 공유해요.

### 초상화 굽기 (tools/bake-portraits.mjs)
- **방식:** 개발 단계에서 headless 브라우저로 각 캐릭터의 상반신을 표정 4종으로 렌더해요.
- **출력:** `public/portraits/<id>_<expr>.webp`, 256px.
- **캐시:** 초상화는 크기가 작고(목표 2MB 이하) 첫 화면부터 쓰여서 프리캐시해요.
- **연결:** `portraitKey`가 이 이미지를 가리켜요. 이미지가 없으면 기존 벡터 초상화를 써요.

### 테스트
- **단위:**
  - 17명 모두 Look3D와 초상화 4종 파일이 있음.
  - 조합 중복 없음.
  - 걷기 목표 지점이 built 조각 안에만 있음.
- **E2E:** 성 화면에 캐릭터 메시와 애니메이션이 있고, 콘솔 에러가 없음.

## 성능 목표 (Galaxy S25 · 데스크톱 headless 기준)
- **구역 화면:** 그리기 호출 ≤ 400, 삼각형 ≤ 200k.
- **구역 모델 첫 다운로드:** 조각 + 캐릭터 합쳐 4MB 이하.

## 리뷰 중점
- 복구 수 0(입구 홀만)과 5(완성)에서의 카메라와 화면 채움.
- 연출 도중 화면 전환, 연타, 오프라인.
- 기존 세이브(복구 수 3인 구역 등)를 열었을 때 바로 올바른 모양이 나오는지(연출 없이).
- 잠긴 구역과 전체지도 탭.
- 캐릭터 3명 + 가구가 함께 있을 때 프레임.
