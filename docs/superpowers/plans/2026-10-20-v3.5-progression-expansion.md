# v3.5 레벨 재설계 + 새 구역·체인 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 레벨을 어렵고 의미 있게 만들고(해금·구역 입장 레벨), 새 체인 2종과 새 구역 2개(제21~30화)를 추가해 게임을 길게 만든다.

**Architecture:**
- **core 규칙:** `core/rules/levels.ts`가 경험치 곡선, 경험치 출처, 해금표를 맡는다.
  - `computeZoneProgress`가 플레이어 레벨을 받아 구역 입장을 판단한다.
  - 보관함 크기는 `bagSize(level)` 함수로 바뀐다.
- **데이터 추가:** 체인과 구역은 기존 데이터 표(`CHAINS`, `ROOMS`, `ZONE_MODULES` 등)에 추가한다.
- **밸런스:** 실제 액션만 쓰는 봇 시뮬레이션 테스트로 맞추고 고정한다.

**Tech Stack:** TS core(순수), Vitest, Svelte 5, Three.js.

**Spec:** `docs/superpowers/specs/2026-10-20-v3.5-progression-expansion-design.md`

## Global Constraints
- 세이브 키·DB 이름은 바꾸지 않는다.
- 새 저장 필드는 없다. 레벨·구역·체인 해금은 모두 기존 값(`playerLv`, `rooms`)에서 계산한다.
- 재화는 `economy.grant`/`spend`로만 바꾼다. 💎는 레벨업 3, 구역 완성 50 그대로다.
- 한국어 UI·주석·커밋. 커밋은 `feat(v3.5.0): ...` 형식이다.
- 규칙은 core에 두고 테스트를 먼저 쓴다.

## Review Focus
- **진행이 레벨보다 앞선 기존 세이브** (예: Lv3인데 정원 진행 중): 진행한 구역은 열려 있고, 다음 구역만 잠긴다. → Task 1 테스트
- **해금 레벨을 넘긴 세이브를 불러올 때:** 촛불·비단 생성기가 없으면 지급한다. → Task 2 테스트 (`ensureGenerators`)
- **보관함:** 복원할 때 `bagSize`보다 많은 아이템이 있어도 버리지 않는다(최대 12칸까지). → Task 1 테스트
- **레벨 미달일 때:** 복구 액션 거절, 다음 이야기 버튼 잠금 표시, 주문은 입장할 수 있는 구역 기준. → Task 1 테스트 + Task 5 화면 확인
- **새 구역 30개 장소:** 레시피 모델이 실제로 있고, 조각 배치가 맞고, 창문형 조각 뒤가 막혀 있다. → Task 3 테스트

  - `progress.ts`: `gainXP`가 새 보상을 쓰고, 해금 체인 생성기를 지급한다.
  - `board.ts`, `orders.ts`, `castle.ts`: 경험치·보관함 크기
  - `progression.ts`: `computeZoneProgress(rooms, playerLv)`가 `lockedZone`과 `nextSpotLockedLv`를 돌려준다.
  - `castle.renovate`: `levelLocked` 거절
  - `holiday.ts`, `restore.ts`(보관함 12칸 상한)
- **Test:** `tests/unit/levels.test.ts`
